# INC-2026-031: Order history N+1 query after orders-service 2.1.0 saturated the DB pool

> Synthetic postmortem for the simulated environment (training/evaluation data).

## What happened

orders-service 2.1.0 loaded order lines in a loop (one query per order). Under normal traffic the 8-connection pool stayed fully checked out and requests timed out waiting for connections ('timed out waiting for a database connection').

## How it was detected and diagnosed

Pool saturation coincided with the deploy; pg_stat_statements showed one statement with thousands of calls per minute. Restarting pods did not help.

## Resolution

Rolled back to 2.0.4; pool drained within a minute. Fix re-shipped as a single JOIN.
